Generalized-place capability fidelity

Does the “capability-first” model (Q8) survive contact with places that don’t group cleanly?

The question Q8 proposes that the shared, host-agnostic repo route every place — aref, gethash, get!, … — through a handful of shared mutation capabilities, with each host supplying only the emitter. But some places may not group: field access (get! → .-field) addresses by a compile-time slot, not a runtime key; list access (nth) is O(n); some places exist on one host only. This demo pushes the vocabulary through the model and counts where it breaks.

Watch for: a place that routes cleanly anyway (no escape hatch needed) vs. one that forces a capability with a single member — a “capability of one”, which is an escape hatch in disguise.
